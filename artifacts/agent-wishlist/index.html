Agent Wishlist

The workbook for Ardengard, our own personal bot team. Each design area collects what is decided, what is still open, and the ideas behind it, so it can become the spec when we start building. Ideas come from Grok Bot, MausBot, Hermes, OpenClaw, Muse, dots, Cue and the open-source field, rewritten in our own words.

Read this first

Built to share, not for daily use
  • Goal since 2026-11-21: build it, talk about it, and share it with your community. You may not use it every day.
  • That changes the main risk: from "you stop using it" (what ended an earlier bot) to "others install something you never ran".
  • So the rule: you run every release yourself, long enough to film the demo, before anyone else installs it. Safe defaults ship on.
The AIOS priority
  • AIOS rule since 2026-11-07: build the system before chasing any opportunity.
  • This counts as system work only for the AIOS integration area.
  • Everything else here is a side project. That is fine, as long as you call it one.
"Our own model" means our own product
  • Our own design, name and code, running on Claude through Claude Code.
  • Training our own language model is not realistic for one person, and the bots would be worse for it.
Clean-room rules for borrowing ideas
  • Ideas, features and behaviors are free to reuse. Code, docs text, artwork and names are not.
  • We write our spec from this page, never from their docs or source.
  • Never use their names: Grok, MausBot, Muse, Claw, Cue.
  • Depending on a permissive library (MIT, Apache) is fine with attribution. Copyleft code (GPL, AGPL) we do not read for implementation at all.
  • Claude has read MausBot's code. For strict clean room, implementation sessions work from this page only.
  • David Ondrej built SuperBot this way: he studied what Grok Bot does and wrote his own. His was a one-day demo with no security work; ours does not ship without the security area.

Path from here

Each step has to earn the next one.

Step 1 · now

See MausBot running

  • A short look on a small server, not a long trial.
  • Note what works and what we would do differently.
Step 2

Fill in the design areas

  • Answer the open questions in each area.
  • A one-week Buzz check before we build on it.
Step 3

Turn areas into the spec

  • Each area becomes a spec chapter in our words.
  • Smallest core first: Buzz, one bot, one computer, Telegram doorbell, memory.
Step 4

Build, run, then share

  • Build in an open repo, posting milestones through /post.
  • Run each release yourself for the demo.
  • Then share with your community, labeled experimental.
